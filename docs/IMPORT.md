# Импорт из Google Sheets: все видимые листы

`import_sheets.js` больше не держит список листов. Он берёт **все видимые листы** из таблиц в `SPREADSHEETS`.

- **Пропускаются:**
  - скрытые листы;
  - листы, в названии которых есть `zwolni` (Zwolnienie, Zwolnienia, Zwolnieni);
  - диаграммы.
- **Названия существующих объектов не меняются.** Лист привязан к объекту по gid, а не по названию. Можно переименовать лист — объект и его название в панели останутся.
- **Новый объект создаётся, только когда в таблице появился новый лист.**

## Что где лежит

| Что | Где |
|---|---|
| Список таблиц | `SPREADSHEETS` в начале `import_sheets.js`. Новую таблицу дописать туда и дать доступ сервисному аккаунту из `google-key.json` |
| Какой лист в какой объект | таблица `import_sheet_map` (миграция `db/migration_import_sheets.sql`) |
| Какие названия пропускать | `EXCLUDE_TITLES` в `import_sheets.js` (сейчас `/zwolni/i`) |
| Проверка без записи | `node import_sheets.js --plan` |

Миграция заполняет `import_sheet_map` из старого списка SOURCES: 83 листа, объекты те же, что были.

## Новый лист

Новый лист становится объектом с названием листа (без пробелов по краям). Но не сразу, если:

| Ситуация | Что делает импорт |
|---|---|
| Название «Kopia arkusza …», «Copy of …», «Копия …» | Ждёт, пока лист переименуют |
| Нет строки заголовков с «Paszport» и «Nazwisko» | Не объект: инструкция, сводка и т. п. |
| Заголовки есть, людей нет (шаблон) | Объект появится с первым человеком |
| ≥60% людей с теми же датами BHP уже есть на другом объекте | Копия чужого листа, не импортирует, чтобы не задвоить людей |
| Объект с таким названием уже привязан к другому листу | Не импортирует: два листа в один объект удаляли бы людей друг у друга |
| За один импорт уже добавлено 10 новых листов | Остальные — в следующий раз (защита от массового создания) |

- **Объект с таким названием уже есть** и не привязан ни к какому листу — новый лист привязывается к нему, новый объект не создаётся.
- **Лист объекта удалили, а его копию переименовали** (те же люди) — копия привязывается к тому же объекту.
  Если старый лист не удалён, а скрыт, импорт ждёт: решать вручную (см. ниже).
- **Новый объект появляется без координатора и региона** — назначить в панели, как обычно.

## Что видно в логе импорта

В конце каждого импорта:
```
  Аркушів імпортовано: 86; пропущено: hidden 1, excluded 1, missing 1
  Нові об'єкти: …
  Нові аркуші до існуючих об'єктів: …
  Очікують: «G&G APT 2»: 300 з 300 людей (з тими ж BHP) уже є на «G&G APT» — схоже на копію
```

## Проверка: `node import_sheets.js --plan`

Ничего не записывает, только читает Google и БД. Показывает по каждой таблице:

- `✓` — лист импортируется в объект;
- `+` — новый лист: какой объект будет создан или к какому существующему привяжется;
- `…` — новый лист, который пока не импортируется, и почему;
- `⚠` — лист **существующего** объекта скрыт, удалён или в названии «zwolni»: объект перестанет обновляться;
- `–` — пропускается (скрыт, zwolnienie, отключён).

## Ручные действия (SQL)

**Посмотреть, что не импортируется:**
```sql
SELECT ss_id, sheet_id, sheet_title, state, note, facility_id, disabled
  FROM import_sheet_map
 WHERE state <> 'active' OR disabled
 ORDER BY state;
```

**Никогда не импортировать лист** (например, список кандидатов):
```sql
INSERT INTO import_sheet_map (ss_id, sheet_id, source_name, origin, state, disabled)
VALUES ('<ID таблицы>', <gid>, '<название листа>', 'manual', 'held', true)
ON CONFLICT (ss_id, sheet_id) DO UPDATE SET disabled = true;
```

**Привязать лист к существующему объекту** (например, объект перенесли на новый лист, а старый скрыли):
```sql
-- 1. старый лист этого объекта отключить, чтобы он не вернулся при раскрытии
UPDATE import_sheet_map SET disabled = true
 WHERE ss_id = '<ID таблицы>' AND sheet_id = <старый gid>;

-- 2. новый лист привязать к объекту
INSERT INTO import_sheet_map (ss_id, sheet_id, facility_id, source_name, origin, state)
VALUES ('<ID таблицы>', <новый gid>, <id объекта>,
        (SELECT name FROM facilities WHERE id = <id объекта>), 'manual', 'active')
ON CONFLICT (ss_id, sheet_id) DO UPDATE SET
  facility_id = EXCLUDED.facility_id, source_name = EXCLUDED.source_name,
  origin = 'manual', state = 'active', note = NULL, disabled = false;
```

- gid листа — число после `#gid=` в адресе листа, или в выводе `--plan`.
- ID таблицы — часть адреса между `/d/` и `/edit`.

## Состояния в `import_sheet_map`

| state | Что значит |
|---|---|
| `active` | импортируется |
| `hidden` | лист скрыт |
| `excluded` | в названии «zwolni» или это диаграмма |
| `missing` | листа в таблице больше нет |
| `held` | новый лист ждёт, причина в `note` |
| `conflict` | объект уже импортируется с другого листа |

`origin`:
- `legacy` — из старого списка;
- `auto` — найден импортом;
- `manual` — привязан вручную.

Если к одному объекту привязаны два видимых листа, импортируется один:
1. сначала `manual`;
2. потом `legacy`;
3. потом найденный раньше.

## Безопасность

- **Запись в объект — как раньше:** обратная проверка удаляет открытые периоды без часов, которых нет на листе, но не больше 10% объекта.
- **Скрытый, удалённый или переименованный** в «zwolnienie» лист просто не импортируется — ничего не удаляется.
- **Таблица не открылась** (ошибка Google) — её объекты считаются занятыми: лист с таким же названием в другой таблице их не перехватит.
- **Одновременно идёт только один импорт** (блокировка в БД). Второй, например запущенный из консоли при работающем сервере, пропускается.
- **Ручной импорт координатора** обновляет только его объекты, новых не создаёт и состояния других листов не меняет.
