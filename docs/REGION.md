# Раздел «Region» — установка и работа

Светофор (RAG) по объектам для региональных координаторов: доска объектов региона,
карточки красных объектов, сводка по координаторам, настройки для админа.

## Что где лежит

| Файл | Что делает |
|---|---|
| `db/migration_regional.sql` | Схема `reg`: регионы и их региональные координаторы, привязки объектов, пороги, недельные снимки, карточки, функции расчёта. `public` не трогает. |
| `db/seed_regional_2026-09.sql` | Регионы и ответственные по таблице «План/Факт август». |
| `api/regional.js` | API `/api/regional/*`, Telegram-напоминания, расписание. |
| `public/region.html`, `public/js/region.js` | Страница раздела. |
| `index.js` | +3 строки: подключение роутера и расписания. |
| `public/index.html` | +1 пункт меню и маленький скрипт, который показывает его только тем, у кого есть доступ. |

## Установка на сервер (C:\sas-bot)

1. **Бэкап базы**: `pg_dump -Fc sasdb > sasdb_before_region.dump`.
2. **Миграция**: в pgAdmin → Query Tool открыть `db/migration_regional.sql` и выполнить.
   Можно запускать повторно — ничего не сломается.
3. **Сид**: выполнить `db/seed_regional_2026-09.sql`. В конце он выводит три выборки:
   кто за что отвечает, опечатки в названиях объектов (должно быть пусто) и объекты с людьми без привязки.
4. **Файлы**: скопировать `api/regional.js`, `public/region.html`, `public/js/region.js`.
5. **index.js** — добавить три строки (на сервере файл может отличаться от GitHub, поэтому вставкой, а не заменой):
   ```js
   // после: const { router: adminRoutes } = require("./api/admin");
   const regional = require("./api/regional");

   // ПЕРЕД строкой: app.use("/api", apiRoutes);
   app.use("/api/regional", regional.router);

   // в самом конце, после scheduleImport();
   regional.schedule(bot);
   ```
6. **public/index.html** — в меню после «📑 Raporty»:
   ```html
   <div id="regionLink" class="nav-item" onclick="location.href='region.html'" style="display: none">🚦 Region</div>
   ```
   и перед `</body>`:
   ```html
   <script>
   fetch('/api/regional/me', { headers: { 'x-session': localStorage.getItem('sas_session') || '' } })
     .then(function (r) { return r.ok ? r.json() : null; })
     .then(function (d) { if (d && d.has_access) document.getElementById('regionLink').style.display = ''; })
     .catch(function () {});
   </script>
   ```
7. `pm2 restart sas-bot`.
8. Зайти админом → **Region → Ustawienia → «Przelicz 12 tygodni wstecz»**. Это заполнит историю
   (около 10 секунд). Карточки откроются только для последней недели.

## Что донастроить сразу после установки

- **Warszawa** — назначить регионального (Ustawienia → Regiony). Там же можно добавить второго: регион ведут несколько человек.
- **IDL Psary, Cainiao, ID ROKITNO** — сейчас без ответственного (в таблице по двое). Назначить одного.
- **Без региона**: CEVA Piotrków Trybunalski well, Action Zamienie SAS EAST BRIDGE, Partners Łowicz SAS,
  Hydro Chrzanów SAS, ID Konin Żagański (Moroz).
- **G&G** — если клиент действительно сворачивает объект, отметить как структурный
  (Ustawienia → Przypadki strukturalne). Объект станет серым и не будет портить показатели.

## Как считается статус

Раз в неделю, в понедельник в 6:00, за прошлую неделю (пн–вс), по последним 28 дням.

- **Объект** = группа по `facilities.group_name` (IDL Psary = APT + SAS + WELL).
- **Ротация** = уходы (кроме переводов) ÷ средняя численность, в пересчёте на 28 дней.
  Зелёный ≤ 12%, жёлтый ≤ 25%, красный > 25%.
- **Дожитие** = пороги 30 и 80 дней с весами 1 и 4, как у координаторов: засчитывается,
  если человек в кадре на конец окна. Зелёный ≥ 75%, жёлтый ≥ 40%, красный < 40%.
  Если возможных весов меньше 8 (меньше двух человек на пороге 80 дней), критерий не считается.
- **NN** = дни без причины ÷ (рабочие дни + NN + UN + L4 + URL). **По умолчанию только показывается**
  и на статус не влияет: включить (`abs_enabled` = 1), когда проверите, что NN заносятся честно.
- **Статус объекта** — худший из критериев.
- **Малые объекты** (меньше 10 человек) считаются по окну 91 день.
- **Выход из красного** — две недели подряд ниже порога.
- `rezygnacja` (не вышли на работу) и `przeniesiony` (переводы) в расчёт не входят. TEST-логины исключены.

Пороги откалиброваны по данным июня–сентября так, чтобы красной была примерно нижняя четверть объектов.
Все пороги меняются в Ustawienia → Progi без правки кода.

### Произвольный период «od–do»

Сверху переключатель «Tydzień / Okres od–do».

В режиме периода статус каждого объекта считается за весь выбранный период:
- та же логика и те же пороги;
- ротация пересчитана на 28 дней;
- без правила выхода из красного и без длинного окна 91 день для малых объектов.

Функция `reg.rag_period(od, do)` из `db/migration_period.sql` — это `reg.rag_raw` с окном, равным периоду.
Для 28 и 91 дня она даёт те же цифры, что и недельный пересчёт.

Как считаются колонки и плитки в режиме периода:
- **«Tyg. czerw. w okresie»** — сколько недельных пересчётов в периоде были красными, например «5 z 11».
- **«Tygodnie w okresie»** — статусы этих недель, до 26 последних.
- **Плитки:**
  - «Średnio w okresie» считается по недельным пересчётам;
  - «Wyszły z czerwonego» — красные в первую неделю периода и не красные в последнюю;
  - карточки — открытые в периоде.
- **Карточка объекта** считается за весь период:
  - статус и три показателя;
  - списки уходов и NN;
  - «Zbliżają się do progu» — 14 дней после «do».

  Под показателями виден статус последнего недельного пересчёта (по нему открываются красные карточки).
  История статуса — недели из недельных пересчётов: 12 недель, а при длинном периоде весь период, до 26 недель.
  Недели вне периода бледнее.
  Блок «Rozmowy i ankiety» всегда показывает состояние на сегодня.
- **Вкладка «Koordynatorzy»** тоже считается за период.

### Ссылка на карточку объекта

`region.html#site=<объект>` открывает карточку сразу. Дополнительно можно передать период:
- `&from=ГГГГ-ММ-ДД&to=ГГГГ-ММ-ДД` — режим «od–do»;
- `&week=ГГГГ-ММ-ДД` — неделя; если она ещё не пересчитана, берутся `from`/`to`;
- `&week=last` — последняя пересчитанная неделя.

Так Pulpit kierownika открывает объекты с тем же периодом, что выбран на пульте.
Период из ссылки не меняет сохранённый выбор в разделе Region.

## Карточки красных объектов

- Открываются автоматически, когда объект становится красным. Срок — 3 рабочих дня (праздники не учитываются).
- Обязательные поля: причина из списка, план действий, срок, ответственный.
- Закрываются сами, когда объект выходит из красного.
- Telegram (нужен `telegram_chat_id`; при нескольких региональных пишем каждому):
  - пн после расчёта — региональным список новых красных;
  - пн–пт 9:00 — напоминание, если до срока меньше суток;
  - просрочено — сообщение админам и региональному (один раз);
  - объект красный 6 недель подряд — сообщение админам;
  - сразу после сохранения карточки — ответственному, если его назначили или поменяли причину, план или срок
    (кроме случая, когда ответственный сам сохраняет карточку);
  - координатор объекта добавил заметку — региональным этого региона.

## Архив объектов (Ustawienia → 📦 Archiwum obiektów, только админ)

Объект, с которым больше не работаем: кнопка **📦** в таблице «Obiekty» (можно указать причину).
Фильтр «tylko bez ludzi» показывает кандидатов — объекты, где по графику никто не работает (с датой последнего дня работы).

Что происходит с объектом в архиве:
- **Wyjazdy / przyjazdy** — нет в списках, плане набора, сводках и напоминаниях;
- **Region** — нет на доске и в истории недель, новые красные карточки не открываются, открытая закрывается (`close_reason = archived`);
- **Tablica zarządu** — не входит в показатели (и за прошлые периоды — сравнение остаётся честным);
- **Rozmowy** — его люди не попадают в риск, разговоры и анкеты; открытые разговоры отменяются, запланированные анкеты не уходят;
- **Poleć znajomego** — новым не уходит стартовый пакет (история ответов и премий остаётся);
- привязка к региону и координатору закрывается.

Данные не удаляются. **«Przywróć»** возвращает объект с прежним регионом и координатором (с сегодняшнего дня).
Если в архиве у объекта по графику ещё кто-то работает, число подсвечено красным — проверьте даты последнего дня.
Таблица: `reg.site_archive`, миграция `db/migration_archive.sql`.

## Доступ

- **Админ** (`coordinator_auth.is_admin`) — все регионы и настройки.
- **Региональный** — только регионы, где он назначен в `reg.region_leads`.
  У одного региона может быть несколько региональных: все видят регион, получают уведомления и заполняют карточки.
  Отдельная роль в `coordinators.role` не нужна.
- **Координатор объекта** — только просмотр, раздел называется «Moje obiekty»:
  - видит объекты, где он координатор по текущей привязке (Ustawienia → Obiekty),
    и объекты, где он ответственный по незакрытой карточке;
  - доска, карточка объекта (показатели, история, кто подходит к 30/80 дням, уходы, NN) и вкладка «Karty» — по этим объектам;
  - карточку красного объекта видит без редактирования: причина, план, срок, ответственный;
    если ответственный он, это отмечено «👤 Ty»;
  - может добавлять заметки о ходе работы, региональный получает их в Telegram;
  - не видит вкладку «Koordynatorzy», другие объекты и настройки.
- Остальные раздел не видят.

## Важно

- **Снимки после записи не меняются.** После смены порогов или привязок историю нужно пересчитать
  кнопкой в Ustawienia. Так прошлые недели не «плывут» от ежечасного импорта.
- Смена ответственного действует **с даты**. На последней неделе доски новый ответственный виден сразу;
  прошлые недели остаются за прежним. Чтобы переназначить на всю историю — поставить раннюю дату и пересчитать 12 недель.
- Удалить раздел полностью: `DROP SCHEMA reg CASCADE;` и убрать строки из `index.js`.
