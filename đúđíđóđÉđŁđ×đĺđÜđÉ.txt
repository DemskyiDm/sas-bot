НОВЕ У ВЕРСІЇ 5
  1) ПОСАДА (Stanowisko) І ОКРЕМО ПРІЗВИЩЕ / ІМʼЯ З ТАБЛИЦЬ
     • Імпорт бере колонку «Stanowisko» (за заголовком, де б вона не стояла) — посада зберігається для кожного
       періоду (на різних обʼєктах може бути різна). Немає колонки на аркуші — посада в базі не змінюється;
       порожня клітинка — посада порожня.
     • «Nazwisko» і «Imię» тепер зберігаються й окремо (для листів на медогляд). Поки імпорт їх не заповнив —
       ділимо «ПРІЗВИЩЕ ІМʼЯ» за першим пробілом.
     • Показується: панель → Pracownicy — колонка «Stanowisko» після «Obiekt» (і в Excel); у Telegram — лише в картці
       працівника в боті («Посада: …»). У мініпанелі (години, аванси) — ні.
     • Заповнюється при першому імпорті після рестарту (усі працівники оновляться один раз — імпорт трохи довший).
  2) МЕДОГЛЯД — замовлення одним листом у клініку
     • Telegram: мініпанель → «Заявки» → «Медогляд». Панель: меню «🩺 Badania lekarskie».
     • День або діапазон (до 31 дня): «Сьогодні / Завтра / Цей тиждень / Наступний тиждень» або дати «з – по».
       Список — хто має BHP у ці дні на обʼєктах координатора (крім rezygnacja). Усі позначені, зайвих можна зняти.
     • Лист польською: таблиця + Excel — Lp, Nazwisko, Imię, Paszport, Przedsiębiorstwo (обʼєкт), Stanowisko, Data BHP,
       Data badania, Adres (поки порожня). Data badania = дата відправки, але не пізніше BHP.
       Тема: «Badania lekarskie — BHP 18.10.2026 — <координатор> (N os.)».
     • Адресати — окремий список від авансів (клініка): спільні (додає адмін) + свої; минулі — вибрані одразу.
     • Замовлені лишаються в списку з позначкою «✉ zamówiono …» і повторно не відправляються.
  3) ПАНЕЛЬ (веб): Zaliczki → кнопка «✉ Wyślij do biura (N)» — те саме, що в Telegram (ті самі адресати й позначки).
     У панелі є вибір зрізу (Moje obiekty / Region / Cała firma — що доступно); у Telegram — перемикач, як раніше.

НОВЕ У ВЕРСІЇ 4: «ВІДПРАВИТИ В ОФІС» ЧЕРЕЗ GMAIL
  Пошта — Gmail (пароль застосунку) або Microsoft 365; перемикання — один рядок у .env (MAIL_PROVIDER).
  Мініпанель → «Рішення» → Аванси → «✉ Відправити в офіс · N»:
  • схвалені аванси за 31 день, ще не надіслані; позначені всі, зайві можна зняти;
  • «Кому»: спільні адреси (додає адмін, позначка «офіс») + свої; кому слали минулого разу — вибрано одразу;
  • один лист польською: таблиця в листі (Lp, Nazwisko i imię, Paszport, Obiekt, Data BHP, Data wniosku, Kwota 300 zł,
    Godziny w m-cu wniosku, Zatwierdził, Razem) + той самий Excel у вкладенні;
  • координатор — у копії, «Відповісти» — йому (e-mail з Admin panel → Koordynatorzy → Email);
  • надіслані позначаються «✉ в офісі …» і вдруге не пропонуються; помилка — аванси лишаються, причина на екрані.

1) GMAIL (≈10 хв, без адміна)
   а) Новий акаунт Google, напр. sas.zaliczki@gmail.com — лише для цього.
   б) myaccount.google.com → Безпека → Двоетапна перевірка → увімкнути.
   в) myaccount.google.com/apppasswords → назва «KoorPanel» → Створити → скопіювати 16 символів (видно один раз).
      Пароль застосунку скидається, якщо змінити основний пароль акаунта, — тоді створити новий.
   г) Перший вхід із сервера Google може вважати підозрілим — якщо прийде лист «Це ви?», підтвердити.
   Ліміт Gmail — 500 листів на добу, з запасом.
   Попросіть бухгалтерію додати адресу в довірені (перший лист з Gmail фільтр може покласти в спам).

2) СЕРВЕР
   а) У C:\sas-bot один раз:   npm install nodemailer
   б) pgAdmin → db\migration_tg_coord.sql ще раз (можна запускати повторно).
   в) Скопіювати всі файли пакета із заміною. Нові: api\mail.js, bot\office.js.
   г) .env — додати:
        MAIL_PROVIDER=gmail
        GMAIL_USER=sas.zaliczki@gmail.com
        GMAIL_APP_PASSWORD=abcd efgh ijkl mnop        (пароль застосунку, пробіли можна лишити)
        MAIL_FROM_NAME=SAS Zaliczki                    (необовʼязково — імʼя відправника)
   ґ) pm2 restart index
   Якщо щось не так, на екрані «Відправити в офіс» зверху написано, чого бракує
   (немає nodemailer / немає GMAIL_USER чи пароля), а при помилці входу — «Gmail не прийняв вхід …».

3) ПЕРШИЙ ЗАПУСК
   • Адмін: мініпанель → Рішення → Аванси → «Відправити в офіс» → додати адресу бухгалтерії з позначкою
     «для всіх координаторів».
   • Координатор: схвалити аванс → «Відправити в офіс» → адресат → «Надіслати». Копія листа — у «Надісланих» Gmail.

ПЕРЕЙТИ НА MICROSOFT 365 ПІЗНІШЕ (коли буде скринька фірми) — лише .env, код той самий:
     MAIL_PROVIDER=microsoft
     MS_TENANT_ID=…  MS_CLIENT_ID=…  MS_CLIENT_SECRET=…  MAIL_FROM=zaliczki@домен
   Що має зробити адмін Microsoft: спільна скринька; App registration з Microsoft Graph → Application permissions →
   Mail.Send + Grant admin consent; Client secret (Value + дата закінчення); бажано New-ApplicationAccessPolicy лише на цю скриньку.

ВСТАНОВЛЕННЯ З НУЛЯ (якщо версій 1–3 ще немає) — додатково до кроку 2:
   index.js — ВСТАВКИ (файл не замінювати):
     а) ВИЩЕ рядка app.use("/api", apiRoutes);
          app.use("/api/tg", require("./api/tg").router);   // Telegram: мініпанель і привʼязка
     б) у app.post("/webhook", ...) — одразу ПЕРЕД рядком  await handleUpdate(bot, req.body);
          if (await require("./bot/coord").onUpdate(bot, req.body)) return;   // координатори: кнопки заявок, привʼязка, пошук
     в) в кінці, поруч з flow.schedule(bot); medcheck.schedule(bot); …
          require("./bot/coord").schedule(bot);
   .env:  TG_WEBAPP_URL=https://sas-panel.duckdns.org/tg/   COORD_DIGEST_TIME=07:30   ADVANCE_STD=300
   Caddy перезапускати не треба.

Перевірено на копії тестової бази: Gmail — через локальний SMTP-сервер, як справжній (вхід паролем застосунку,
неправильний пароль → зрозуміла помилка й аванси лишаються, From «SAS Zaliczki» <gmail>, копія й «Відповісти» —
координатору, польські літери в темі, таблиця, Excel відкривається) — 12 перевірок; Microsoft — 26; решта — 60 + 18.
