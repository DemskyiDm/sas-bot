PRZYPISANIA — ВСЕ ПРИВЯЗКИ В ОДНОМ МЕСТЕ (Region → 🔗 Przypisania)
====================================================================

Миграцию и замену файлов делать ПОДРЯД, без перерыва. Пока работает старый код, админ-панель
пишет привязки напрямую, и такие изменения после миграции пересчёт перезапишет.

1) Миграция. Можно запускать повторно; вся миграция идёт одной транзакцией, при ошибке ничего не меняется.
   Нужны уже установленные migration_regional.sql и migration_archive.sql.
      psql -U postgres -d sasdb -f db/migration_przypisania.sql
   В конце будут три таблицы — прочитать:
     1. «Kto STRACIŁ dostęp» — должно быть пусто, кроме причин «nieaktywny koordynator» и «obiekt w archiwum».
        Если есть «SPRAWDŹ» — не продолжать, прислать мне вывод.
     2. «Nowy dostęp» — кто получил больше, чем было:
        - главный или вспомогательный получает всю группу объекта (APT + SAS + WELL);
        - региональный получает просмотр своего региона.
     3. Сводка: было / стало строк, сколько «do sprawdzenia».
   Старая таблица сохраняется в reg.coordinator_facilities_backup (откат описан в docs/PRZYPISANIA.md).

3) index.js — одна правка (в архиве есть и целый файл: если ваш index.js такой же, как на GitHub, можно просто заменить).
   НАЙТИ:
      app.patch("/api/facility-settings/:id", async (req, res) => {
        const { field, value } = req.body;

   ЗАМЕНИТЬ НА:
      app.patch("/api/facility-settings/:id", requireAuth, async (req, res) => {
        const { field, value } = req.body;

        // Admin — każdy zakład; koordynator — tylko z prawem edycji (główny / pomocniczy z edycją, Region → Przypisania)
        if (!req.coordinator.is_admin) {
          const can = await db.query(
            `SELECT 1 FROM coordinator_facilities WHERE coordinator_id = $1 AND facility_id = $2 AND is_primary`,
            [req.coordinator.coordinator_id, parseInt(req.params.id, 10) || 0],
          );
          if (!can.rows.length) return res.status(403).json({ error: "Tylko podgląd — brak prawa edycji na tym zakładzie" });
        }

   requireAuth и db в index.js уже подключены (строки 2 и 5).
   public/js/modules.js заменить ОБЯЗАТЕЛЬНО вместе с этой правкой, иначе сохранение настроек заклада перестанет работать.

4) pm2 restart sas-bot

5) Зайти админом → Region → 🔗 Przypisania:
   • Жёлтый баннер «do sprawdzenia» — бывшие привязки из админ-панели. Сейчас это вспомогательные С РЕДАКТИРОВАНИЕМ,
     права ни у кого не урезаны. Решить по каждой:
       ✓        — оставить редактирование;
       ✎ edycja — нажать, станет 👁 podgląd (только просмотр);
       ✕        — убрать.
     Или сразу для всех: «Wszystkim → tylko podgląd» / «Wszystkim zostaw edycję».
   • Фильтр «bez głównego» — объекты с людьми без главного координатора, назначить.
   • Проверка: зайти под координатором с просмотром — объект виден, а при сохранении часов будет «Tylko podgląd».

ЧТО ГДЕ ТЕПЕРЬ
   Region → 🔗 Przypisania (только админ):
     - объект → регион, главный (с даты), вспомогательные 👁 / ✎;
     - регион → региональные;
     - координатор → Dezaktywuj / Aktywuj;
     - 📦 архив.
   Region → Ustawienia — только пересчёт, пороги и структурные случаи. Регионы, объекты и архив переехали в Przypisania.
   Админ-панель:
     - учётки, логины и пароли — как были;
     - пункт «🔗 Przypisania → Region» ведёт на новую вкладку;
     - старое прямое прикрепление закрыто.

ПРАВА
   Главный               — видит и редактирует; отвечает за объект в Region, Wyjazdy, Rozmowy.
   Вспомогательный ✎     — видит и редактирует (часы, авансы, wolne, импорт, работники, настройки заклада).
   Вспомогательный 👁    — только видит.
   Региональный          — видит весь свой регион в главной панели, без редактирования; в Region ведёт регион, как раньше.
   Права работают на всю группу объекта (IDL Psary = APT + SAS + WELL).
   Смену главного указывают датой «od»: сегодня или раньше, будущую дату панель не примет.
   Новый главный сразу получает редактирование, прежний его теряет. Если прежний должен помогать — добавить его вспомогательным.

НЕАКТИВНЫЙ КООРДИНАТОР
   • Не входит в панель, открытые сессии закрываются сразу.
   • Нет доступа к объектам.
   • Не получает сообщений в Telegram. Срочные задачи Rozmowy по его объектам идут региональному или админу.
   • Объекты, где он главный, подсвечены красным — назначить другого.
   • «Aktywuj» возвращает все его привязки.
