# Импорт со всех видимых листов — установка

В архиве:
- `import_sheets.js` — полная замена;
- `db/migration_import_sheets.sql` — таблица привязок «лист → объект»;
- `docs/IMPORT.md` — как это работает и ручные действия.

Остальные файлы не меняются. Раздел Wyjazdy/przyjazdy работает с новым импортом как раньше.

## Шаги (C:\sas-bot)

1. **Копия старого файла:**
   ```
   cd C:\sas-bot
   copy import_sheets.js import_sheets.old.js
   ```

2. **Миграция** (повторный запуск безопасен):
   ```
   psql -U postgres -d sasdb -f db\migration_import_sheets.sql
   ```
   В конце выведется список из 83 листов старого списка и объектов, к которым они привязаны.
   Пустой объект означает, что такого объекта ещё нет в базе: импорт создаст его с названием из старого списка, как и раньше.

3. **Положить новый `import_sheets.js`.** Сервер пока работает со старым, пока не перезапущен.

4. **Проверка без записи:**
   ```
   node import_sheets.js --plan
   ```
   Займёт 1–3 минуты. Если в консоли «кракозябры» — сначала `chcp 65001`,
   или сохранить в файл: `node import_sheets.js --plan > plan.txt` и открыть в Блокноте.
   Смотреть на:
   - `⚠` — лист существующего объекта скрыт, удалён или в названии «zwolni». Этот объект перестанет обновляться.
     Если объект живой — раскрыть лист в Google (или написать мне).
   - `+` — какие объекты будут созданы. Если какой-то лист не объект (кандидаты, архив), отключить его до перезапуска.
     SQL в `docs/IMPORT.md`, раздел «Никогда не импортировать лист»; gid есть в выводе `--plan`.
   - `…` — новые листы, которые пока не импортируются, с причиной.

5. **Перезапуск:**
   ```
   pm2 restart index
   ```
   (или как называется процесс). Первый импорт — через 5 минут после старта, дальше каждые 4 часа.
   Ручной импорт из панели тоже работает.

## Откат

```
copy import_sheets.old.js import_sheets.js
pm2 restart index
```

- Таблица `import_sheet_map` старому импорту не мешает.
- Объекты, которые успел создать новый импорт, остаются.
