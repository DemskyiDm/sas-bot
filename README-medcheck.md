# Медосмотры: вечерняя сверка BHP ↔ таблица «badania lekarskie»

Каждый день в 22:00 бот sas-bot шлёт в Telegram сводку:

- **BHP сегодня** — кто уже есть в листе «Orzeczenia lekarskie» (✅) и кого нет (❌, с паспортом и координатором объекта);
- **🟢 Добавлены сегодня** — кого не было на прошлых сверках, а сегодня внесли;
- **🔴 Всё ещё нет** — BHP в прошлые дни (окно 14 дней), в таблицу так и не внесли;
- **➖ Сняты с проверки** — пропали из базы: rezygnacja, перенесли BHP, период удалён.

Кто начал — из `worker_facility_history.bhp_date` (то же, что в панели). Поиск в таблице — по паспорту (`workers.login`), если не нашли — по ФИО в любом порядке слов (помечается ⚠️). Кириллические буквы в номере паспорта (Е/О/С…) не мешают. Если человек в таблице есть, но самая свежая дата его строки (odbiór / data zgłoszenia) старше BHP на 180+ дней — помечается «⚠️ старая запись» (повторный найм, медосмотр, скорее всего, нужен новый).

Статусы `rezygnacja` и логины `TEST_%` не проверяются.

## Файлы

| Файл | Что |
|---|---|
| `bot/medcheck.js` | новый — сверка, отчёт, отправка, планировщик |
| `db/migration_medcheck.sql` | новый — таблица `med_check_missing` (кого не было и когда закрыли) |
| `index.js` | +require, 2 эндпоинта, `medcheck.schedule(bot)` в конце |

`medcheck.patch` — то же самое одним патчем (лёг чисто на текущий `main`). Папка `files/` — полные файлы, если удобнее скопировать.

## Установка

**1. Доступ к таблице.** У тебя на таблице «Tylko wyświetlanie» — поделиться ты не сможешь, это делает владелец. Узнай почту сервисного аккаунта:

```
findstr client_email C:\sas-bot\google-key.json
```

и попроси владельца «badania lekarskie» дать этой почте доступ **Przeglądający**.

**2. Код.**

```
cd C:\sas-bot
git apply medcheck.patch
```

(или скопировать `files\bot\medcheck.js`, `files\db\migration_medcheck.sql`, `files\index.js` — но `index.js` только если локально он не отличается от GitHub).

**3. Миграция.**

```
psql -U postgres -d sasdb -f db/migration_medcheck.sql
```

**4. `.env`** — ID таблицы из URL (между `/d/` и `/edit`):

```
MED_SHEET_ID=...
MED_SHEET_TAB=Orzeczenia lekarskie
MED_CHECK_CHAT_ID=          # то же значение, что GAP_ADMIN_CHAT_ID, или ID группы (бот должен быть в группе); можно несколько через запятую
MED_CHECK_TIME=22:00
MED_CHECK_FROM_DATE=2026-10-13   # чтобы первая сводка не вывалила хвосты за 2 недели; убери, если хвосты нужны
```

Пустой `MED_CHECK_CHAT_ID` → шлёт админам панели, у которых привязан Telegram.

**5.** `pm2 restart sas-bot`

## Проверка

Посмотреть отчёт без отправки и без записи в базу (токен админа — как для `/api/gaps/preview`):

```
GET  /api/med-check/preview?session=<токен>
GET  /api/med-check/preview?session=<токен>&date=2026-10-12
```

Отправить сводку сейчас:

```
POST /trigger/med-check?session=<токен>          — как в 22:00, состояние сохраняется
POST /trigger/med-check?session=<токен>&dry=1    — отправить, но не сохранять
```

Повторный запуск в тот же день даёт тот же отчёт — «Добавлены сегодня» не теряются.

Если таблица не читается (нет доступа, пустой лист, < 100 строк) — в чат уходит «⚠️ Сверка не сделана: <причина>», состояние не трогается.

## Остальные настройки `.env`

| Переменная | По умолчанию | Что |
|---|---|---|
| `MED_CHECK_DAYS` | 14 | сколько дней держать «хвосты»; старше — тихо закрываются |
| `MED_CHECK_SKIP_STATUSES` | rezygnacja | какие статусы периода не проверять |
| `MED_CHECK_OLD_DAYS` | 180 | порог «старой записи»; 0 — выключить |
| `MED_CHECK_SHOW_PASSPORT` | 1 | паспорт у тех, кого нет; 0 — не показывать |
| `MED_CHECK_SHOW_PRESENT` | 1 | поимённо тех, кто есть; 0 — только число + ⚠️ |
| `MED_CHECK_MIN_ROWS` | 100 | защита от битого чтения таблицы |
| `MED_CHECK_ENABLED` | 1 | 0 — выключить |

## Ограничения

- Данные о BHP — на момент последнего импорта (раз в 4 часа). Кого координатор внёс в свой лист после последнего импорта, в сегодняшней сводке не будет — он появится завтра в «Всё ещё нет», если в таблице медосмотров его тоже нет.
- Колонки ищутся по заголовкам (`paszport`, `nazwisko`, `imie`, `zakład`, `odbiór w dniu`, `data zgłoszenia…`) в первых 10 строках — переставлять колонки можно, переименовывать `paszport`/`nazwisko` нельзя.
- Проверено на локальном PostgreSQL 16 с фейковой таблицей (дни 1–2, повтор, удаление строки, выход за окно, битое чтение, длинный отчёт). Реальное чтение Google Sheets не прогонялось — нет ключа и доступа к таблице.
